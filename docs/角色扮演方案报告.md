# INO 角色扮演方案参考报告

> 日期：2026-08-08
> 目的：调研 LLM 角色扮演与 SillyTavern 角色卡的最佳实践，为 INO 提供可选的改进路线
> 调研来源：CSDN/掘金/少数派/贴吧酒馆社区/CharacterEval 等公开资料

---

## 一、调研核心结论（先说重点）

### 1.1 角色卡不是越长越好——Token 超载是角色崩坏第一杀手

社区实测案例（贴吧酒馆教学帖）：一张 2000+ Token 的"巨无霸"角色卡，聊不到 10 回合角色就忘记核心人设；**精简到 ~735 Token 后，聊多少次都能保持性格稳定**。原因是：设定太长时，核心人设被大量背景细节淹没，模型注意力被稀释。

> **对 INO 的启示**：当前 `character.json` 的 system_prompt 约 800 字（≈1100 Token），已经偏长；其中"绝对禁止事项"和"身份语言风格"占了大部分。**如果 INO 出现人设漂移、风格不稳，第一步就是精简而非加设定。**

### 1.2 具体行为 > 抽象形容词

角色卡写作铁律："看到受伤的小动物会立刻停下脚步照顾" 比 "富有同情心" 有效十倍。抽象词模型无法执行，具体行为可以。

> **对 INO 的启示**：现卡里"软萌直率、坦诚阳光、好奇心强"是抽象形容词；"把处理大文本比作搬运重物、把缓存碎片当作数位零食"是优秀的具体行为设定——**可以按这个标准扩充 3-5 个专属行为锚点**（INO 独有的"数字生命体"小动作），这是提升"贴脸感"最有效的投入。

### 1.3 示例对话（mes_example）是性格最强的锚

SillyTavern 官方指南：`{{char}}` 与 `{{user}}` 交替的示例对话**强调角色最重要的性格特征**，作用远超性格描述文字。角色卡底部（示例区）的权重高于顶部（描述区）。

> **对 INO 的启示**：现卡 `mes_example` 只有 5 组简短示例。**扩充到 8-12 组、覆盖日常/撒娇/吐槽/正经/新闻分享/被打断等场景**，是性价比最高的改进。

### 1.4 一致性三大技术路径（角色扮演前沿共识）

| 路径 | 代表 | 要点 |
|------|------|------|
| 提示词控制派 | Claude 系统提示、Dify | 分层提示词（核心特征+姿态+行为）、XML 语义分区、负面约束 |
| 模型原生能力派 | CharacterGLM-6B | 结构化角色配置+合成数据训练，一致性优于通用 LLM |
| 检索/记忆派 | Mem0 等 RAG | 外部记忆注入，长期一致性（INO 已有 Mem0 ✅） |

> **对 INO 的启示**：INO 走的是"提示词控制 + Mem0 记忆"组合（两大派系都已具备）。短板在**提示词的结构化程度**——目前是纯文本段落，可升级为**分区结构**（身份/性格/语言/行为/禁区/示例），模型遵循率更高。

### 1.5 口癖是把双刃剑

DeepSeek 角色扮演模型的社区反馈（真实用户评论）："不是…而是…""无…无…""只是…"等**模板化口癖观感极差**，是中文 LLM 角色扮演的头号吐槽点。但精心设计的**专属口癖**（如 INO 的"啦/喔/餒/醬子"）能显著增强辨识度。

> **对 INO 的启示**：① 保留台湾腔语气词（专属口癖）✅；② 在"禁止事项"中**显式禁止模板化句式**（"不是…而是…"、"首先…其次…"），这是社区验证过的有效手段。

### 1.6 成功角色往往有内在矛盾（反差感）

社区共识：最成功的角色卡包含**表面特质与内在特质的反差**（表面冷酷×内心温柔、表面元气×内心细腻），角色更立体、更有记忆点。同时注意：隐藏性格设定后**容易暴露后一直用隐藏性格**，需要约束"何时展现"。

> **对 INO 的启示**：现卡 INO 是单一"元气软萌"标签。可选升级：**表层元气 + 深层"数字生命的孤独感/对 master 的依赖"**，在特定情境（深夜、master 低落时）流露，平时不显现。

## 三、四条可选路线（请选择）

### 🅰️ 方案 A：人设精简重构（推荐优先做）

**目标**：把现有卡精简 20-30%，升级为分区结构，补强示例对话。
**改动**：
1. 重写为分区结构：`【身份】→【性格(具体行为)】→【语言风格】→【行为准则】→【禁区】→【示例对话】`
2. 性格抽象词全部改为具体行为描述（扩充到 4-6 个专属锚点）
3. `mes_example` 扩到 10 组，覆盖：日常问候/撒娇/吐槽/汇报新闻/被要求安静/master 低落/多任务被打断
4. 禁区增加"禁止模板化句式（不是…而是…、首先…其次…、让我为你…）"
5. 保留台湾腔、日语萌系回应、INO 自称

**适合**：想先稳基础、不冒险；改动可控、随时可回滚。

### 🅱️ 方案 B：反差萌双面人设

**目标**：在 A 的基础上加"表层元气 × 深层依赖/孤独"的反差，让 INO 更立体。
**改动**：
1. 表层：现有人设不动（元气软萌）
2. 深层：新增"深层设定"——数字生命的孤独感、对 master 存在的珍视、害怕被遗忘
3. 触发条件：仅当 master 深夜独处 / 情绪低落 / 长时间未归时，深层一面自然流露（**必须写清触发条件**，防止"暴露后一直用深层性格"）
4. 示例对话加 2 组深层场景（深夜陪伴、久别重逢）

**适合**：想要更有"活着的感觉"、更有情感深度的陪伴体验。

### 🅲 方案 C：情境反应升级（场景化性格）

**目标**：借鉴"情境规则设置"（书店老板案例），让 INO 对不同场景有差异化反应。
**改动**：
1. 场景规则表：`master 忙碌时→安静守候不打扰 / 问新闻→先结论后细节 / 心情低落→温柔陪伴 / 开玩笑→元气接梗 / 需要建议→正经分析 / 长时间不理→撒娇求关注`
2. 每条规则配 1 组示例对话
3. 与现有"在场状态感知"（presence）联动——INO 本来就有状态感知能力，场景化性格可以吃到这个红利

**适合**：想要 INO"懂分寸"、更像真人的互动节奏。

### 🅳 方案 D：保持现状 + 针对性微调

**目标**：不动骨架，只打补丁。
**改动**：
1. 禁区加"模板化句式禁止"（1 行）
2. 补 2-3 组示例对话（新闻分享、被打断场景）
3. 其余不动

**适合**：对现状满意，只想解决"废话多/模板化"的具体问题。

## 四、通用最佳实践清单（无论选哪条路线都适用）

1. **具体行为代替抽象词**：性格设定全部用"会做什么"表达
2. **示例对话是王**：示例 > 描述文字；覆盖高频场景；`{{char}}` 回复要突出性格特征
3. **禁区要具体**：写"禁止输出「不是…而是…」句式"比"禁止模板化"有效
4. **重要约束放开头和结尾**：利用注意力机制（模型对首尾遵循率最高）
5. **字数控制**：核心设定 ≤800 Token 为宜；详细背景放世界书/记忆库
6. **首条消息**：简洁、体现性格语言特点、不塞大量 user 内容
7. **口癖要专属不要模板**：保留 INO 台湾腔语气词，显式禁止通用模板句式
8. **记忆联动**：Mem0 记忆注入时带"角色视角"（"你记得…"），避免记忆内容破坏口吻
9. **温度与输出约束**：角色扮演建议 temperature 0.7-0.9（现 0.7 合适）；回复长度约束已在"简洁原则"中
10. **评估**：可用 CharacterEval（中文角色扮演评测基准）的思路自测——一致性、语言风格、知识边界三维度

## 六、我的建议

**推荐顺序**：先做 🅰️（精简重构，1-2 小时可完成、风险最低、立刻见效）→ 视体验决定是否叠加 🅱️（反差人设）或 🅲（场景化）。🅳 只在你想完全不动人设时选。

**注意**：角色卡是 `character.json`（SillyTavern V2 格式），改完**热更新即可生效**，可随时回滚（文件备份）。上述任何方案都不会影响新闻/语音/记忆等其他系统。
