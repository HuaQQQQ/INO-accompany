## 一、新闻来源（现状）

INO 的新闻**没有固定媒体源**，而是用 7 个预设关键词（见 `config.yaml → news.queries`）向**免费搜索聚合接口**发查询，取前 4~5 条结果：

| # | 来源 | 用途 | 链接格式 |
|---|------|------|----------|
| 1 | **Google News RSS**（主） | 常规抓取 / 搜索 / 侧边栏更新 | `news.google.com/rss/search?q=...&hl=zh-CN&gl=CN` |
| 2 | **Bing News RSS**（备） | 仅当 Google 整批失败时兜底 | `bing.com/news/search?q=...&format=rss` |
| 3 | **DuckDuckGo HTML**（补） | 仅 `web_search` 场景，用于拿"真实原文链接" | `html.duckduckgo.com/html/` |

**实际落地的原始媒体**（从 `news_cache.json` 抽样）：新浪财经/新浪网、搜狐网、QQ、网易、中关村在线、超能网、驱动之家、17173、财联社、东方财富、21财经等——都是搜索聚合结果，不是主动订阅。

### 数据流

```
config.yaml 7 个查询词
      ↓ (每 3600s 或手动 force_refresh)
Google News RSS ──失败──▶ Bing News RSS
      ↓ 每查询取前 4 条，按标题精确去重
news_cache.json（时间戳 + 新闻数组）
      ↓
├─ 前端右侧 News Feed（/api/news，取前 8 条渲染）
├─ INO 自主行为 5% 概率"好奇分享"（随机挑 1 条）
├─ 对话中提到新闻时：匹配标题 → DDG 搜原文 → 抓正文 → 注入上下文
└─ 4 个工具：get_sidebar_news / web_search / read_news_detail / manage_news_topics / update_sidebar_news
```

## 二、现状问题（均有代码/数据证据）

### P0 · 功能层面

1. **Google 链接是加密跳转壳，正文 90% 读不了**
   - 缓存中几乎所有 `link` 都是 `news.google.com/rss/articles/CBMi...`（Google 的 base64 跳转壳）。
   - `fetch_article_content()` 遇到 `news.google.com` 直接拒绝（`news_fetcher.py:116`），所以 `read_news_detail` 工具对绝大多数缓存新闻**必然失败**。
   - `app.py` 的新闻详解逻辑被迫"多绕一圈"：先 `search_web` 搜标题 → 用正则从 DDG 结果里抠真实链接 → 再抓正文，成功率取决于 DDG 是否被墙。

2. **时效性差，老新闻长期霸榜**
   - Google News RSS 的搜索排序**不是严格时间序**，缓存里混着 2024-09、2025-01、2025-05 的旧闻（如"RTX 5090 官宣售价"），2026-08 的新闻反而排后面。
   - 没有按 `pubDate` 排序，没有过期过滤（如 72 小时新鲜度），也没有"同主题只留最新 N 条"的裁剪。

3. **缓存条目字段不完整**
   - `update_sidebar_with_search()` 生成的条目只有 `title/date/query`，**缺 `link` 和 `source`**（`news_fetcher.py:404-408`）——缓存前 4 条 ROG 新闻就是例子，前端点击后 INO 无法展开详情。

4. **标题带" - 来源名"后缀，显示冗余**
   - Google RSS 的 title 自带来源（如"Win11怎么更新显卡驱动_新浪财经"、`title.text` 未经清洗），`get_sidebar_news_prompt` 和前端直接展示，标题里" - 中华网"这类尾巴重复且难看。

### P1 · 健壮性层面

5. **无重试/退避，超时太短**
   - Google 4s、Bing 5s、DDG 8s、正文 10s 全部一次性请求，失败即跳过；国内网络环境下 Google 经常超时，抓取结果时多时少。

6. **Bing 只兜底不合并，来源面窄**
   - 逻辑是 `if not fetched_for_query`：只要 Google 成功抓到 ≥1 条，Bing 结果就完全丢弃。同一个查询两种引擎结果重合度高，等于少一个信息面。

7. **抓取全串行，刷新慢且无写锁**
   - 7 个查询 × 最多 2 个源全部 `for` 循环同步请求，一次刷新最坏 ~60s+；多线程并发调用 `get_news(force_refresh=True)` 可能同时写坏 `news_cache.json`（没有锁，只有 try/except）。

8. **正文提取器过于简陋**
   - `_TextExtractor` 手写 HTMLParser 只剥离 script/style、按标签拼换行，无段落权重、无句子边界保护；800 字符硬截断可能截在句子中间；多数新闻站有反爬/动态渲染，`apparent_encoding` 探测也偶发乱码。

### P2 · 工程整洁层面

9. **死配置 + 死代码**
   - `config.yaml` 的 `news_prompt_chance: 0.05` 全项目无任何代码读取；
   - `NewsFetcher.get_news_prompt_snippet()` 定义了但无人调用——"随机把新闻注入上下文"的意图没有真正落地。

10. **去重粗糙**
    - 只按 title 完全相等去重；同一新闻在 Google/Bing 标题微差（带/不带来源后缀）就会重复。

## 四、开源 Agent Skill 调研（可魔改的现成方案）

按用户要求调研了 OpenClaw（原 Clawdbot，GitHub 385k star）、Anthropic 官方 skills、Superpowers、ClawHub 技能市场，**结论：有 1 个高度对口的现成 skill 值得魔改**。

### 🏆 首选：`cclank/news-aggregator-skill`（ClawHub 10.8k 下载）

- **仓库**：`github.com/cclank/news-aggregator-skill`（Apache 风格，SKILL.md + scripts/）
- **为什么对口**：功能 = INO 新闻系统的"完整升级版"
  - **44+ 源**，含中文源：36氪、华尔街见闻、腾讯新闻、微博热搜、少数派、InfoQ 中文、V2EX + 国际化（BBC、Guardian、Reuters via Google News fallback——和 INO 现状同思路）
  - **自定义 OPML 订阅**（`fetch_user_feeds.py`）：把 INO 的 7 个关键词换成"订阅清单"，可直接塞入 IT之家/量子位/澎湃等实测源
  - **`--deep` 正文抓取**：下载全文做深度分析——正好解决 INO"正文读不了"的痛点
  - **统一报告模板 + 反幻觉规则 + 关键词自动扩展**（"AI"→"AI,LLM,GPT,Claude,Agent,RAG"）
  - **`daily_briefing.py` 预设简报**：general/finance/tech/social/ai_daily 多套 profile
- **魔改成本**：低。`requirements.txt` 只有 `requests + beautifulsoup4`（INO 项目已具备）；核心 `fetch_news.py` 41KB 可裁剪出中文源部分，或直接复用其 `rss_parser.py`（见下）
- **可白嫖的实现细节**：`rss_parser.py`（4.2KB）用 BeautifulSoup 宽容解析 RSS/Atom，带 **3 次重试 + 1s/2s 退避**、CDATA 清洗、`content:encoded` 优先取正文摘要——INO 的 `news_fetcher.py` 可直接移植这段逻辑替换手写 `_TextExtractor` + ET 解析。

### 次选：`paudyyin/daily-news-cn`（每日新闻日报 v2.3）

- 卖点最契合："双引擎交叉验证 + **官方媒体优先** + 900 秒超时容错"——正好补 INO 缺的"可信度"维度
- ⚠️ 但 GitHub 仓库已 404（ClawHub 页面还在，751 下载），**源码不可得**，只能参考其设计思路（双引擎交叉验证、官方媒体优先级排序）

### 参考：其他相关 skill

| Skill | 来源 | 可借鉴点 |
|-------|------|----------|
| `hot-news-summary` | ClawHub | 微博/抖音/知乎**多平台热榜**聚合（弥补 INO 无热榜能力） |
| `lknik/news-feed`（3.7k 下载） | ClawHub | 极简 RSS 读取器心智：一个 SKILL.md + 一段 Python 循环抓取 |
| OpenClaw 内置 `blogwatcher` | `openclaw/openclaw/skills/` | "订阅列表 + scan 扫描 + 新文章标记"的 RSS 监控心智模型，可借鉴到 INO 的 `manage_news_topics` |
| OpenClaw 内置 `summarize` | `openclaw/openclaw/skills/` | URL→正文→LLM 摘要流程；但依赖外部 summarize CLI + API key，**不适合 INO**（INO 用本地 LM Studio，改造成本高） |
| Anthropic 官方 `anthropics/skills` | GitHub | 全部是文档/办公类（docx/pdf/xlsx），**无新闻类** |
| `obra/superpowers`（258k star） | GitHub | 软件开发方法论（brainstorming/TDD），**与新闻无关** |

### 魔改路线图（结合 §三 实测源 + §四 skill）

1. **移植 `rss_parser.py`** → 替换 INO 的 ET 解析 + 手写 `_TextExtractor`，正文提取升级（BeautifulSoup + 重试退避 + CDATA 清洗）
2. **新增"订阅源"层** → 模仿 `blogwatcher`/OPML 模式，在 `config.yaml → news.sources` 配置 §三 实测可用源（IT之家/量子位/澎湃 API/第一财经 API/百度热搜 + RSSHub 镜像路由），作为与 Google/Bing 搜索源**并行合并**的第二通道
3. **权威媒体优先排序** → 借鉴 `daily-news-cn` 思路，按 §三 可信度分级给来源打权重，同主题新闻优先采用 ★★★★ 以上来源
4. **`--deep` 正文抓取** → 迁移 `fetch_news.py` 的深读模式，让 `read_news_detail` 对订阅源条目直接读正文（订阅源无跳转壳问题）
5. **反幻觉与关键词扩展规则** → 直接抄 SKILL.md 里的 Rules 段（"只用 JSON 里的数据，绝不编造"、"Smart Keyword Expansion"）

## 五、改进建议（按优先级）

### 立即可做（低代码量、高收益）

| 改动 | 说明 |
|------|------|
| **引入实测国内订阅源** | §三 第一/二梯队直接接入：IT之家、量子位、爱范儿、少数派 RSS + 澎湃/第一财经 API + 百度热搜，替换 30% 的 Google 依赖，正文立即可读 |
| **移植 rss_parser.py 逻辑** | BeautifulSoup 解析 + 3 次重试退避，替换 `_TextExtractor` 和裸 ET 解析 |
| **按 pubDate 排序 + 新鲜度过滤** | 写入缓存前按时间降序，剔除超过 72h 的旧闻；同 query 只保留最新 6 条 |
| **补全字段 + 标题清洗** | `update_sidebar_with_search` 补 `link/source`；title 去掉" - 来源"、" _来源"后缀 |
| **刷新加锁 + stale-while-revalidate** | `threading.Lock` 保护缓存写；刷新失败时继续返回旧缓存并记录时间，而不是清空 |

### 近期值得做（中等工作量）

| 改动 | 说明 |
|------|------|
| **魔改 news-aggregator-skill** | 裁剪 `fetch_news.py` 保留中文源 + OPML 订阅层，形成 INO 自己的 `news_sources.py` 模块 |
| **抓取并发化** | `ThreadPoolExecutor(max_workers=4)` 并行处理各查询，刷新耗时从 ~60s 降到 ~15s |
| **RSSHub 自建** | Docker 一条命令部署，解锁新华社/央视/人民网/微博热搜等全部国内路由，摆脱公共镜像 503 |
| **可信度权重排序** | 按 §三 分级给 source 打分，同主题优先权威源；报告模板借鉴 news-aggregator-skill 的统一格式 |
| **正文提取升级** | `trafilatura` 或移植 skill 的 `--deep` 模式；截断按句子边界 |

### 后续方向（高成本、看需求）

| 改动 | 说明 |
|------|------|
| **新闻偏好学习** | 结合 Mem0 记忆：INO 每次"讲新闻"后把用户感兴趣的 query 权重上调，自动调整订阅主题 |
| **语义去重** | 用现有 embedding（bge-small-zh）对标题向量化去重，替换精确匹配 |
| **本地新闻库 + 定时后台刷新** | 独立线程每 30 分钟静默刷新，前端永远拿到新鲜缓存，点击不再触发同步抓取 |
